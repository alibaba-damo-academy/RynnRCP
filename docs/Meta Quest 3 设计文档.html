Meta Quest 3 设计文档

面向接入开发者说明当前 Quest 双臂 Web 仿真的数据链路、末端位姿与关节角接口， 以及扩展键盘和普通游戏手柄控制的推荐实现。接手后先完成本地仿真闭环，再复用 RCP 的关节位置 Action 接入真实 FR3。

目标平台：双 Franka FR3 控制频率：60 Hz 末端坐标：XYZ + RPY / 四元数 输出：7 关节 + 夹爪 / 每臂

1. 交接结论

当前后端已经完成工作空间限制、末端目标限速、URDF IK、关节限速和仿真状态输出。 键盘与手柄只需生成末端目标，并复用现有 POST /api/target。 本地调试需要直接回放关节角时，使用 POST /api/joints。
当前可用

末端位姿控制

页面滑块已经通过绝对末端位姿驱动 IK，键盘和手柄可以复用同一目标变量和发送函数。

当前可用

关节角输出

/api/state 返回仿真关节角；RCP 主臂服务以 joint_state 发布关节目标。

建议新增

输入适配与停机语义

增加键盘、Gamepad API、使能键、输入源仲裁，以及释放使能键时立即保持当前位置的接口。

4. 当前位姿和关节角如何获得

完整数据链：从 Quest 原始数据到 joint_state

4.1 坐标转换的 10 个执行步骤

  1. 接收左右手柄原始数据

    UDP 接收线程读取 leftController 和 rightController。 每侧包含三维位置、xyzw 四元数、时间戳、Grip、Trigger 和标定按钮状态。

    输入：position{x,y,z}、rotation{x,y,z,w} 输出：Quest 原始位姿 pQ、RQ
  2. 检查数据来源和新鲜度

    只接受配置的 source_ip；带时间戳的数据保持单调递增。最近数据超过 stale_timeout_s 后暂停输出，避免继续使用旧手柄姿态。

    检查：发送端 IP、时间戳、最近收包时间 失败行为：停止生成新的关节目标
  3. 按 X+A 建立标定参考

    双臂模式要求左右标定按钮同时按下。上升沿触发时，分别保存当前原始位姿 pQ,cal 和 RQ,cal，并把标定后的手柄相对位姿置零。

    保存：左右手柄各自的标定位置和标定旋转 结果：中立手柄姿态对应零平移、单位旋转
  4. 计算相对标定位置

    每次收到新包，先减去标定位置：

    ΔpQ = pQ,now - pQ,cal
  5. 把位置增量转换到 RCP 坐标

    使用当前 coordinate_basis 左乘位置增量：

    pR = Bp × ΔpQ

Bp = [[0, 0, -1],
      [1, 0,  0],
      [0, 1,  0]]

XR = -ZQ
YR =  XQ
ZR =  YQ

    转换后的语义固定为 X 向前、Y 向左、Z 向上。

  6. 计算并转换相对旋转

    先求当前手柄相对标定姿态的旋转，再用 rotation_basis 完成坐标基变换， 最后应用旋转分量符号配置。 

    ΔRQ = RQ,now × transpose(RQ,cal)
RR  = BR × ΔRQ × transpose(BR)
qR.xyz = qR.xyz × [-1, -1, +1]

BR = [[ 0, 0, 1],
      [-1, 0, 0],
      [ 0, 1, 0]]

    为保持四元数连续，如果新旧四元数点积小于零，代码会把新四元数整体取反。 这不会改变物理旋转，只会避免数值表达跳号。

  7. Grip 按下时建立离合参考

    每次 Grip 从松开变为按下时，系统记录当前 RCP 手柄相对位姿 pR,start / RR,start，同时记录机械臂当前目标 panchor / Ranchor。这是第二层参考点。

    标定参考：决定手柄轴和中立姿态 Grip 参考：决定本次拖动从机械臂哪里开始
  8. 计算 Grip 按下期间的位姿增量 
    ΔpG = pR,now - pR,start
ΔRG = RR,now × transpose(RR,start)

    松开 Grip 时冻结当前目标并清除离合参考；下一次按下会重新建立参考，因此松开期间的手柄移动不会进入机械臂目标。

  9. 叠加到 FR3 绝对末端目标 
    ptarget = panchor + translation_scale × ΔpG
Rtarget = ΔRG × Ranchor

    ptarget / Rtarget 是 FR3 基坐标系下的绝对末端目标，也是键盘、手柄和滑块最终应该生成的数据。

  10. 限制目标、求解 IK 并输出关节角

    仿真线程以 60 Hz 依次处理：

    1. 按 workspace_delta_limits_m 裁剪绝对位置。
    2. 按最大平移和旋转速度，把 tracking pose 向 target pose 推进一步。
    3. 以上一帧关节角为种子执行 URDF IK。
    4. IK 收敛后，按关节速度和加速度限制平滑到新的关节解。
    5. IK 未收敛时保留最后合法关节角，并在状态中报告误差。
    6. 通过 /api/state 或 RCP joint_state 输出关节角。

4.2 一次完整的平移数值示例

目标：从 Quest 原始坐标计算 FR3 绝对末端位置

1. 标定时 Quest 位置：pQ,cal = [0.10, 1.20, -0.30]

2. 当前 Quest 位置：pQ,now = [0.13, 1.24, -0.38]

3. 相对标定位置：ΔpQ = [0.03, 0.04, -0.08]

4. 映射到 RCP：pR,now = [0.08, 0.03, 0.04]

5. 本次 Grip 按下起点：pR,start = [0.02, 0.01, 0.00]

6. Grip 内增量：ΔpG = [0.06, 0.02, 0.04]

7. 机械臂锚点：panchor = [0.30, 0.20, 0.35]

8. translation_scale = 1.0 时：ptarget = [0.36, 0.22, 0.39]

后端随后按 Home 相对工作空间裁剪这个目标，再执行平滑和 IK。调试方向时先让单个 Quest 原始轴只变化一个小量，观察 target_pose.position 中哪个 RCP 轴发生变化。

4.3 /api/state 中的三个机械臂位姿

字段含义交接时的用途
ee_pose 当前仿真关节角经过 FK 得到的末端位姿。 确认模型实际到达的位置。
tracking_pose 经过末端速度限制后，当前 IK 正在跟踪的中间位姿。 排查输入目标变化过快时的跟踪过程。
target_pose 滑块、Quest、键盘或手柄最终要求的绝对目标。 检查输入适配器是否生成了正确目标。
joint_positions 当前平滑后的关节角。 Three.js 显示、日志检查和下游关节角接入。

4.4 从末端目标到 joint_state 的 9 个执行步骤

  1. 写入绝对末端目标

    Quest 桥接器、键盘、手柄和网页滑块最终都调用 UrdfJointSimulation.set_target_absolute(position, quaternion)。 这里写入的是 FR3 基坐标系下的目标位姿，还不是关节角。

  2. 裁剪目标并保存 target_pose

    后端先按 Home 相对工作空间限制位置，再保存为 _desired_position / _desired_rotation；快照中的 target_pose 就来自这两个期望值。

  3. 60 Hz 调用 advance()

    SimulationRunner 每帧调用一次仿真推进。键盘和游戏手柄只需要持续更新目标， 不应该各自实现 IK 或关节限速。

  4. 把末端目标限速为 tracking_pose

    _move_vector_toward() 限制平移速度， _move_rotation_toward() 限制旋转速度。得到的中间位姿是当前帧真正送给 IK 的目标。

  5. 以上一帧关节角为种子执行 URDF IK

    chain.solve_ik(next_position, next_rotation, current_joints) 返回 IkResult.joint_positions、收敛状态、位置误差和旋转误差。

  6. 平滑并限制关节解

    IK 收敛后，_smooth_joint_target() 按关节速度和加速度约束逐步逼近关节解， 再由 chain.clamp() 执行关节限位。IK 不收敛时保留最后一组合法关节角，避免跳变。

  7. 生成仿真内部 q / dq

    simulation.joint_state() 返回平滑后的 joint_positions 和 joint_velocities。夹爪值在这一层独立维护，不属于机械臂 IK 解。

  8. 添加夹爪并拼接左右臂

    单臂 get_joint_positions() 按配置在机械臂关节后追加夹爪； 双臂控制器再按“左臂关节、左夹爪、右臂关节、右夹爪”顺序拼接。双 FR3 含双夹爪时共 16 维。

  9. 发布 RCP joint_state

    dual_joint_leader_integration.yaml 通过 ProtocolInputAdapter 以 60 Hz 暴露 observation.robot.joint_state；Teleop 再把它转发为执行端的 action.robot.joint_position。 

simulation.joint_state()
{
  "joint_positions": [q1, ..., q7],
  "joint_velocities": [dq1, ..., dq7]
}

单臂 Leader observation
{"joint_positions": [q1, ..., q7, gripper]}

双 FR3 Leader observation
{"joint_positions": [left_q1, ..., left_q7, left_gripper,
                     right_q1, ..., right_q7, right_gripper]}
最容易混淆的三个量： target_pose 是输入设备要求的位置，tracking_pose 是本帧 IK 的限速目标， ee_pose 是当前关节角 q 经过 FK 得到的实际位置。 RCP 对外发布的主臂状态是 observation.robot.joint_state，不是 ee_pose。 POST /api/joints 仅用于关节级本地调试，它会绕过末端目标、末端限速和 IK。

5. 本地仿真接口

默认地址为 http://127.0.0.1:8765。以下命令可直接验证后端。

5.1 启动双臂仿真

cd robots/meta_quest3
source venv/bin/activate

rynnrcp-meta-quest3-sim \
  --config rynnrcp_robot_meta_quest3/config/sim/franka_fr3_dual.yaml

5.2 读取状态

curl http://127.0.0.1:8765/api/state

5.3 发送末端目标：键盘和手柄使用此接口

curl -X POST http://127.0.0.1:8765/api/target \
  -H 'Content-Type: application/json' \
  -d '{
    "side": "left",
    "ee_pose": {
      "position": [0.30, 0.20, 0.35],
      "orientation_rpy": [-3.14, 0.0, 0.0]
    },
    "gripper": 0.5
  }'

后端会进行工作空间裁剪、目标限速、IK 和关节平滑。前端无需自行计算关节角。

5.4 直接发送关节角：用于回放和数据格式调试

curl -X POST http://127.0.0.1:8765/api/joints \
  -H 'Content-Type: application/json' \
  -d '{
    "joint_positions": [
      0.0, -0.785, 0.0, -2.356, 0.0, 1.571, 0.785, 1.0,
      0.0, -0.785, 0.0, -2.356, 0.0, 1.571, 0.785, 1.0

双 FR3 的数组顺序固定为：左 7 个关节、左夹爪、右 7 个关节、右夹爪。 /api/joints 会直接更新仿真关节状态，适合本地回放；连续末端控制使用 /api/target 以保留 IK 和平滑链路。

5.5 本地闭环验证步骤

  1. 启动时先关闭 Quest 输入

    启动命令暂时不带 --quest，让页面只有滑块和 HTTP API 一个控制源，便于确认基础链路。

  2. 确认 Home 和模型状态

    打开页面后确认左右臂均显示 IK 已收敛、位置误差接近零、关节数量为每臂 7 个并带夹爪。

  3. 记录状态基线

    请求 /api/state，保存左右臂的 target_pose、tracking_pose、 ee_pose 和顶层 joint_positions。后续每次测试都与这份基线比较。

  4. 单轴发送一个小目标

    只修改左臂 X，例如在当前绝对 X 上增加 0.01 m，Y、Z 和姿态保持原值。 先观察 target_pose 变化，再观察 tracking_pose 和 ee_pose 逐步跟上。

  5. 依次验证六个自由度

    分别测试 +X、+Y、+Z、+RX、+RY、+RZ，每次只改变一个轴。记录页面模型运动方向、IK 状态和误差。

  6. 验证工作空间限制

    发送略超出配置范围的目标，确认后端把位置限制在 Home 加 workspace_delta_limits_m 的边界，状态持续有效且关节角没有突变。

  7. 验证关节角回放接口

    先发送示例 16 维 Home 数据，再故意发送 15 维数组。正确行为分别是返回新状态，以及返回 HTTP 400 和明确的维度错误。

  8. 回到 Home 并开始输入设备开发

    调用 POST /api/home，确认双臂平滑回到 Home。此时基础后端闭环通过，可以开始接键盘和游戏手柄。

6.1 从本地仿真接到单台 FR3 的步骤

  1. 完成本地仿真验收

    先通过第 5 节全部检查，确认末端方向、IK、工作空间、关节顺序、使能释放和 Home 行为。 保存一组已验证的 Home 关节角和小范围末端测试目标。

  2. 在连接 FR3 的 Ubuntu 主机准备环境 
    cd robots/franka_fr3
bash setup_franka_fr3.sh
source venv/bin/activate
  3. 启动执行端 FR3 Server 
    rynnrcp-server \
  --config rynnrcp_robot_franka_fr3/config/franka_fr3_server.yaml

    记录终端打印的真实 gRPC 地址，并确认 Manifest 中存在 observation.robot.joint_state 和 action.robot.joint_position。

  4. 只读检查真实机械臂状态

    读取 8 维 joint_state，确认前 7 维关节角处于配置限位内，第 8 维夹爪在 0–1。 FrankaController.get_ee_pose() 已能读取实测末端位姿；当前 Integration 未把它声明为公开 Observation，需要时新增 ee_pose 描述后再通过 RCP 读取。

  5. 启动键盘/手柄主臂 Server

    主臂侧继续使用 URDF IK，把末端目标转换成 8 维关节 Observation。 初次真机联调使用单右臂配置和较低速度，确认稳定后再处理双臂执行端拆分。

  6. 在 Teleop 中配置唯一控制流 
    source: observation.robot.joint_state
target: action.robot.joint_position
rate:   60 Hz

    先保持运动使能释放，观察主臂和执行端状态均在线、维度均为 8。

  7. 低速执行单轴动作

    按住使能键执行约 5 mm 的 +X 位移并释放。确认 FR3 移动方向、实测关节变化、目标超时保持和急停均符合预期， 再依次验证其他轴和夹爪。

  8. 确认双臂执行架构

    当前双臂主臂输出是 16 维合并向量，单台 FR3 执行端只接受 8 维。 双真机接入需要明确采用“两台 FR3 Server 分别接收 8 维”还是新增一个双臂执行 Server 负责拆分， 再配置对应的 Teleop 控制流。

7. 键盘控制方案

键盘输入表达末端速度。页面维护当前按键集合，每个动画帧根据 dt 积分成新的 targets[side]，最后调用现有 scheduleTarget(side)。

按键功能建议行为
1 / 2选择左臂 / 右臂界面突出显示当前控制侧。
Space运动使能键按住才更新目标，松开时调用保持。
W/SX 前 / 后默认平移速度 0.05 m/s。
A/DY 左 / 右方向遵循 RCP 坐标系。
R/FZ 上 / 下目标仍受工作空间配置限制。
↑/↓绕 X 旋转默认角速度 0.3 rad/s。
←/→绕 Y 旋转按页面当前末端姿态连续积分。
Q/E绕 Z 旋转用于末端 Roll/Yaw 微调。
[ / ]夹爪闭合 / 打开限制在 0–1。
H回到 Home调用现有 /api/home。
使用 keydown/keyup 维护按键状态，以动画帧时间积分目标。 浏览器的按键重复频率只用于文本输入，不适合作为运动控制频率。

7.1 键盘前端实现步骤

  1. 增加输入状态

    在 dual.html 的 targets 附近增加当前控制侧、按键集合、使能状态、速度配置和上一帧时间。 

    const keyboard = {
  activeSide: "left",
  pressed: new Set(),
  enabled: false,
  linearSpeed: 0.05,
  angularSpeed: 0.30,
  gripperSpeed: 0.50,
  lastFrameAt: performance.now(),
};
  2. 监听物理按键码

    使用 event.code，这样键盘布局变化时 WASD 的物理位置仍保持一致。 对 Space、方向键等浏览器快捷键调用 preventDefault()。 

    window.addEventListener("keydown", event => {
  if (["Space", "ArrowUp", "ArrowDown", "ArrowLeft", "ArrowRight"]
      .includes(event.code)) event.preventDefault();

  if (event.code === "Digit1") keyboard.activeSide = "left";
  if (event.code === "Digit2") keyboard.activeSide = "right";
  if (event.code === "Space") keyboard.enabled = true;
  keyboard.pressed.add(event.code);
});
  3. 以每帧时间积分末端速度

    每个动画帧把按键转换成轴向值，乘以速度和 dt，更新当前侧的绝对目标。 将 dt 限制在 0–0.05 s，可避免页面卡顿恢复时一次跳太远。 

    function keyAxis(positive, negative) {
  return Number(keyboard.pressed.has(positive))
       - Number(keyboard.pressed.has(negative));
}

function updateKeyboard(now) {
  const dt = Math.min(0.05, Math.max(0, (now - keyboard.lastFrameAt) / 1000));
  keyboard.lastFrameAt = now;

  if (keyboard.enabled) {
    const side = keyboard.activeSide;
    const target = targets[side];

    target.position[0] += keyAxis("KeyW", "KeyS") * keyboard.linearSpeed * dt;
    target.position[1] += keyAxis("KeyA", "KeyD") * keyboard.linearSpeed * dt;
    target.position[2] += keyAxis("KeyR", "KeyF") * keyboard.linearSpeed * dt;

    target.orientation_rpy[0] += keyAxis("ArrowUp", "ArrowDown") * keyboard.angularSpeed * dt;
    target.orientation_rpy[1] += keyAxis("ArrowLeft", "ArrowRight") * keyboard.angularSpeed * dt;
    target.orientation_rpy[2] += keyAxis("KeyQ", "KeyE") * keyboard.angularSpeed * dt;

    target.gripper += keyAxis("BracketRight", "BracketLeft")
      * keyboard.gripperSpeed * dt;
    target.gripper = Math.max(0, Math.min(1, target.gripper));

    syncTargetControls(side);
    scheduleTarget(side);
  }
  requestAnimationFrame(updateKeyboard);
}
  4. 释放 Space 时立即保持

    keyup 删除按键状态。Space 释放时只发送一次 /api/hold，避免机械臂继续追踪释放前尚未到达的目标。 

    window.addEventListener("keyup", async event => {
  keyboard.pressed.delete(event.code);
  if (event.code !== "Space" || !keyboard.enabled) return;

  keyboard.enabled = false;
  await post("/api/hold", {
    side: keyboard.activeSide,
    source: "keyboard",
  });
});
  5. 处理页面失焦

    浏览器切换标签页时可能收不到对应的 keyup。监听 blur 和 visibilitychange，清空按键并进入保持状态。

  6. 同步滑块和输入状态提示

    每次程序化修改 targets 后，更新 XYZ、RPY 和夹爪滑块显示；页面顶部显示 “键盘 · 左臂 · 已使能”或“键盘 · 等待 Space”，让交接人能判断输入是否生效。

8. 游戏手柄控制方案

浏览器通过 navigator.getGamepads() 读取标准手柄。每个动画帧读取轴值，经过死区和 曲线处理后转换成末端速度。一个手柄可切换左右臂；两个手柄可分别绑定左右臂。

建议映射

平移与旋转

左摇杆控制 X/Y，LT/RT 控制 Z；右摇杆控制 Pitch/Yaw，LB/RB 控制 Roll。

建议映射

离合与夹爪

A 按住使能；X/B 控制夹爪；D-pad 左右选择机械臂；Start 回 Home。

摇杆处理参数

参数建议初值用途
轴死区0.12消除摇杆中心漂移。
响应曲线sign(x) × |x|³保留中心微调能力，同时覆盖较大速度。

8.1 游戏手柄前端实现步骤

  1. 发现并显示手柄

    监听 gamepadconnected 和 gamepaddisconnected，保存设备索引和 gamepad.id。页面显示已连接设备以及绑定的机械臂侧别。

  2. 标准化摇杆死区

    死区内输出零；死区外重新映射到 0–1，再使用三次曲线：

    function shapedAxis(value, deadzone = 0.12) {
  const magnitude = Math.abs(value);
  if (magnitude <= deadzone) return 0;
  const normalized = (magnitude - deadzone) / (1 - deadzone);
  return Math.sign(value) * normalized ** 3;
}
  3. 读取标准轴和按钮

    每帧重新调用 navigator.getGamepads()。标准映射中，轴 0/1 通常是左摇杆， 轴 2/3 是右摇杆，按钮 6/7 是 LT/RT，按钮 4/5 是 LB/RB，按钮 0 是 A。

  4. 转换成统一末端速度命令 
    command.linear = [
  -shapedAxis(gamepad.axes[1]),             // X：左摇杆前后
  -shapedAxis(gamepad.axes[0]),             // Y：左摇杆左右
  gamepad.buttons[7].value - gamepad.buttons[6].value, // Z：RT - LT
];

command.angular = [
  Number(gamepad.buttons[5].pressed) - Number(gamepad.buttons[4].pressed),
  -shapedAxis(gamepad.axes[3]),
  -shapedAxis(gamepad.axes[2]),
];

command.enabled = gamepad.buttons[0].pressed;
  5. 复用键盘的 TargetIntegrator

    键盘和手柄都输出 linear[3]、angular[3]、夹爪速度和 enabled。同一个积分器更新 targets[side]，避免维护两套运动逻辑。

  6. 处理断开和超时

    当前活动手柄消失、页面失焦或连续 200 ms 未读到有效状态时，发送一次 /api/hold 并释放该侧控制权。

  7. 完成实机手柄映射校准

    不同品牌可能交换按钮编号或轴方向。页面增加“输入监视”区域，显示原始 axes/buttons， 逐项确认摇杆、扳机、肩键和 A/B/X/Start 后再保存映射。

9.3.1 /api/hold 的后端修改顺序

  1. 为双臂仿真增加公开保持方法

    在 DualArmSimulation 中把侧别检查和单臂保持封装成公开方法：

    def hold_current(self, side: str, *, source: str = "manual") -> None:

  2. 在 HTTP Handler 中注册路由

    在 do_POST() 中与 /api/home、/api/target 同级处理：

    elif self.path == "/api/hold":
    source = str(payload.get("source") or "manual")
    if isinstance(self.simulation, DualArmSimulation):
        self.simulation.hold_current(str(payload.get("side") or ""), source=source)

  • 仿真启动后，GET /api/state 持续返回左右臂 16 维控制数据。
  • 键盘选择左右臂准确，未选中的一侧保持最后状态。

  • 姿态控制连续，通过 ±π 附近时不会发生明显跳变。
  • 游戏手柄中心静止时目标不漂移，轻推可微调，满量程可达到配置速度。
  • 目标超过工作空间时被稳定限制，页面显示 IK 状态和误差。
  • IK 不收敛时保持最后合法关节目标，不输出突变关节角。
  • 夹爪始终限制在 0–1，左右臂维度和顺序保持固定。
  • Quest、滑块、键盘和手柄切换时，界面显示当前输入源且目标无跳变。
  • 关节回放接口可接受 16 维数据，维度错误时返回可定位的错误信息。
