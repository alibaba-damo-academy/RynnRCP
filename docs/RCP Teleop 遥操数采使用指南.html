RCP Teleop 遥操数采使用指南

说明 Teleop App 如何发现设备、绑定控制端和执行端、配置控制流、遥操、数据采集、回放和导出。

一句话理解

Teleop App 本身不控制硬件。它连接两个 RCP Server：一个提供控制输入，另一个执行动作并采集数据。 页面里看到的所有状态、图像、动作和采集项，都来自 Server 的 Manifest、Observation 和 Action 描述。

角色关系

角色 含义 典型例子
控制端 Server 提供遥操输入数据，通常只需要 observations。 SO101 Leader、示教臂、手柄、脚本、策略模型。
执行端 Server 接收 action，执行机器人动作，并保存采集数据。 SO101 Follower、真实执行机器人。
Teleop App 连接两个 Server，读取控制端 observation，转换为执行端 action，同时管理采集和导出。 浏览器里的遥操数采页面。

启动顺序

  1. 启动执行端 Server，例如 SO101 follower。
  2. 启动控制端 Server，例如 SO101 leader。
  3. 启动 Teleop App。
  4. 打开浏览器页面，刷新设备，选择控制端和执行端。
  5. 确认控制流，再开始遥操或数据采集。
# 终端 1：执行端
rynnrcp-server --config rynnrcp_robot_so101/config/so101_follower_server.yaml

# 终端 2：控制端
rynnrcp-server --config rynnrcp_robot_so101/config/so101_leader_server.yaml

# 终端 3：Teleop App
rynnrcp-teleop-app

Teleop 默认页面：

http://127.0.0.1:28402

设备发现

Teleop App 会从本机注册表、mDNS 和静态地址发现 RCP Server。Server 启动后会打印真实地址：

Local gRPC: 127.0.0.1:42027
LAN gRPC:   30.150.30.180:42027
情况 怎么做
App 和 Server 在同一台机器 通常能自动发现；也可以手动添加 Local gRPC 地址。
App 和 Server 在同一局域网 优先自动发现；发现不到时手动添加 LAN gRPC 地址。
跨网段或 mDNS 不通 手动添加 Server 终端打印的 LAN gRPC 地址。不要猜端口。
如果同一台 Server 通过本机地址和局域网地址同时出现，页面会按 robot_id 合并显示；用户只需要选设备，不需要关心底层地址来源。

设备匹配

页面选择控制端和执行端时，会读取两个 Server 的 Manifest，用里面的能力判断是否适合当前角色。

检查项 控制端需要 执行端需要
observations 需要，用来读取控制输入。 需要，用来显示执行端状态和图像。
actions 通常不需要。 需要，用来执行遥操指令。
data_collection 通常不需要。 需要采集数据时必须开启。
resources 通常不需要。 需要回放、导出历史采集数据时必须开启。

控制流配置

控制流描述“控制端的哪个 observation 驱动执行端的哪个 action”。最常见配置是：

observation.robot.joint_state  ->  action.robot.joint_position

页面会从 list_observations 和 list_actions 获取可选项，只允许用户选择协议上可以直接匹配的 value 类型。

控制端 Observation 执行端 Action 是否适合直接遥操
joint_state joint_position 适合，常规主从臂遥操。
ee_pose ee_pose 适合，前提是机器人支持末端位姿控制。
joint_state ee_pose 不直接匹配，需要额外运动学转换，当前页面不自动猜。
home、move_to 这类 action 可以在 Server 里存在，但它们不是连续遥操控制流。遥操默认使用 joint_position 这类连续控制 action。

遥操过程

读取控制端状态 App 按控制流读取控制端 observation，例如 observation.robot.joint_state。
发送执行端动作 App 把读取到的协议 value 放进 action frame，调用执行端 run_action_chunk。
显示执行端反馈 App 按用户勾选的 key 读取执行端图像和状态，不需要每次读取全部 observation。

页面会显示控制频率、图像刷新频率、get_obs 耗时、run_action 耗时和连接状态，用来判断当前遥操是否稳定。

数据采集

数据采集发生在执行端 Server。Teleop App 只是告诉执行端 Server：本次 episode 要录哪些协议对象。

采集项 默认选择 原因
Observation，例如 observation.robot.joint_state、observation.front.image 默认勾选 它们是数据集里的状态和传感器数据。
连续控制 Action，例如 action.robot.joint_position 默认勾选 遥操期间会持续发送，是数据集里的 action。
预定义动作，例如 action.robot.home 默认不勾选 这是偶发事件，不是连续控制流。
自定义动作，例如 action.robot.move_to 默认不勾选 只有用户明确要记录这类事件时才手动选择。 
start_collection(
  names=[
    "observation.robot.joint_state",
    "observation.front.image",
    "observation.wrist.image",
    "action.robot.joint_position"
  ],
  collection_id="teleop_dataset_...",
  episode_id="episode_000001"
)

采集数据保存在哪里

原始采集数据保存在执行端 Server 的本地目录。App 不直接扫描远端文件夹，而是通过 Resource 工具查看、读取和打包。

Server data/
  collections/
    manual/
      teleop_dataset_xxx/
        episode_000001/
          collection_meta.json
          streams/
            observation.robot.joint_state/samples.msgpack
            observation.front.image/samples.msgpack
            action.robot.joint_position/samples.msgpack

如果 Server 和 App 在不同机器，回放或导出时 App 会按需临时下载需要的数据。导出完成后，临时文件会清理。

回放

回放用于检查某个 episode 是否可用。页面会从采集数据中读取 action stream，按原始顺序重新发送给执行端。

步骤 说明
选择 episode 在数据管理区展开数据集，点击 episode 的回放按钮。
移动到起始位置 如果配置开启，回放前会先移动到 episode 起点附近。
发送 action 按采集数据里的 action 帧执行。
停止回放 停止后回到初始状态，避免 UI 继续显示执行中。

导出

导出发生在 App 侧。App 从 Server 读取原始采集数据，按指定 FPS 做 nearest 对齐，生成 parquet、视频和 metadata，再打包成 zip。

导出方式 结果
导出单个 episode 生成一个 episode zip。
导出选中 episode 把选中的 episode 编码并打包。
导出整个 dataset 把该 dataset 下所有 episode 一次性打包。

导出时可以启用 RynnBot key 映射：

action.robot.joint_position      -> action
observation.robot.joint_state    -> observation.state
observation.front.image          -> observation.images.front
observation.wrist.image          -> observation.images.wrist
App 和 Server 通信始终使用 RCP key。RynnBot key 映射只发生在导出或云端 App 边界。

页面功能总览

区域 功能
执行端视野 显示执行端 image 类型 observation，可多选需要预览的相机。
执行端状态 / 控制端状态 显示 joint_state、ee_pose 等状态；joint_position 和 ee_pose 用图表展示，其他类型展示内容。
设备选择 选择控制端 Server 和执行端 Server，支持自动发现和手动地址。
控制流 配置 observation 到 action 的映射，可支持多条控制流。
状态监控 显示在线状态、遥操状态、采集状态、控制频率、图像频率、接口耗时。
遥操控制 开始/停止遥操。
数据采集 选择采集项，开始/停止采集，查看每个 stream 的采集帧率。
数据管理 查看本机和 Server 资源，回放、导出、删除采集数据，查看日志资源。

常见问题

问题 处理方式
发现不到 Server 使用 Server 终端打印的 LAN gRPC 地址手动添加；确认网络可达。
执行端没有 action 检查执行端 server config 的 manifest.capabilities.actions 是否为 true，以及 integration 是否声明 actions。
无法拉取历史数据 检查执行端 manifest.capabilities.resources 是否为 true。
遥操延迟大 先看页面里的 get_obs 和 run_action 耗时；再检查网络延迟、图像预览数量和设备负载。
采集项太多 保留需要训练的数据。默认不勾选 home、move_to 这类事件型 action。
