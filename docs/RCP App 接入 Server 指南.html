RCP App 接入 Server 指南

本文面向 App 开发者，说明如何导入 Interface、发现 Server、获取可用工具，以及按协议调用工具。

App 是 RCP Server 的客户端。App 不直接接触机器人 SDK、串口、相机编号、channel、adapter。 App 只使用 Interface、协议工具和协议对象名。

一、App 调用链

App
  -> rynnrcp.interface
  -> Interface gRPC
  -> Server ToolBus
  -> Service
  -> runner / controller

App 只关心：

  • 怎么发现或指定 Server。
  • Server 暴露了哪些工具。
  • Server Manifest 里有哪些 capabilities、components、observations、actions。
  • 如何调用协议工具并处理返回值。

二、导入 Interface

推荐 App 使用协议层封装，不直接操作底层 gRPC。

from rynnrcp.interface import ClientInterface
from rynnrcp.interface.protocol_client import (
    RcpProtocolClient,
    discover_manifests,
    connect_to_server,
)
对象用途
ClientInterface管理发现源，并连接 endpoint。
RcpProtocolClient协议方法封装，例如 get_manifest、get_observations、run_action_chunk、list_policies。
discover_manifests发现可达 Server，并读取每个 Server 的 Manifest。
connect_to_server按 robot_id 解析并连接一个 Server。

三、发现 Server

开发 App 时通常同时启用本机注册表、mDNS 和静态地址。静态地址适合调试，mDNS 适合局域网自动发现。RCP Server 默认使用动态 gRPC 端口，启动后会在终端打印 Local gRPC 和 LAN gRPC 地址；静态地址应填写这个实际地址。

server_address = "127.0.0.1:54241"  # 替换为 Server 终端打印的 Local gRPC 或 LAN gRPC

interface = ClientInterface.with_defaults(
    static_addresses=[server_address],
    local_registry=True,
    mdns=True,
)

endpoints = interface.discover(timeout_s=1.5)
for endpoint in endpoints:
    print(endpoint.address, endpoint.source, endpoint.metadata)

如果只想获得带 Manifest 的可用 Server：

manifests = discover_manifests(interface=interface, timeout_s=1.5)
for manifest in manifests:
    print(
        manifest.robot_id,
        manifest.robot_name,
        manifest.embodiment_type,
        manifest.endpoint.address if manifest.endpoint else "",
    )

四、连接 Server

方式 A：用户选择 endpoint

endpoint = endpoints[0]
client = RcpProtocolClient(interface.connect(endpoint))

方式 B：按 robot_id 连接

client = connect_to_server(
    robot_id="my_robot_follower",
    interface=interface,
    timeout_s=1.5,
)

方式 C：手动地址

client = RcpProtocolClient.connect(server_address)

连接后统一处理返回

RcpProtocolClient 方法返回统一响应对象。业务代码应先检查 ok，成功时读取 payload，失败时显示或记录 message。

response = client.get_manifest(timeout_ms=1000)
if not response.ok:
    raise RuntimeError(response.message)

manifest = response.payload

工具调用失败时，payload 仍可能包含空结构，App 不应继续按成功数据解析：

{
  "ok": false,
  "message": "names is required",
  "payload": {
    "observations": []
  }
}

五、获取可用工具

Server 的工具来自 ToolBus。App 可以先读取工具列表，用于调试、MCP 暴露或 UI 能力判断。

response = client.list_tools(timeout_ms=1000)
if not response.ok:
    raise RuntimeError(response.message)

for tool in response.payload["tools"]:
    print(tool["name"], tool.get("description", ""))

返回 payload 示例：

{
  "tools": [
    {
      "name": "get_manifest",
      "description": "Get the RCP robot manifest.",
      "input": {},
      "output": {
        "robot_id": "str",
        "robot_name": "str",
        "embodiment_type": "str"
      }
    },
    {
      "name": "get_observations",
      "description": "Get latest RCP Observation values.",
      "input": {
        "names": "list[str] # required Observation names",
        "sync": "bool # optional; current server only supports false"
      }
    }
  ]
}

业务 App 通常还需要读取 Manifest 和能力描述：

manifest = client.get_manifest(timeout_ms=1000)
print(manifest.capabilities)
print(manifest.components)
print(manifest.observations)
print(manifest.actions)

六、列出 Observation 和 Action

App 不应写死某个机器人有哪些数据和动作，应从 Server 查询。

obs_resp = client.list_observations(timeout_ms=1000)
act_resp = client.list_actions(timeout_ms=1000)

observations = obs_resp.payload["observations"] if obs_resp.ok else []
actions = act_resp.payload["actions"] if act_resp.ok else []

for item in observations:
    print(item["name"], item["type"], item.get("value_schema"))

for item in actions:
    print(item["name"], item["type"], item.get("input_schema"))

list_observations 返回 payload 示例：

      "type": "image",

字段说明
name完整协议对象名，App 调用时使用这个值。
type协议 value 类型，例如 joint_state、image、joint_position。
component_name所属组件名，可用于 UI 分组。
value_schema/input_schema用于生成表单、校验入参、渲染不同类型数据。

七、调用 Observation 工具

只请求当前页面需要的 observation，不要每次请求全部数据。

selected_names = [item["name"] for item in observations if item["type"] == "joint_state"]

response = client.get_observations(
    selected_names,
    sync=False,
    timeout_ms=1000,
)

if response.ok:
    for obs in response.payload["observations"]:
        print(obs["name"], obs["timestamp"], obs["value"])

sync=true 当前不实现；App 应传 sync=False。

get_observations 返回 payload 示例：

{
  "observations": [
    {
      "name": "observation.robot.joint_state",
      "timestamp": 1782216088.02686,

      "value": {
        "width": 640,
        "height": 360,

八、调用 Action 工具

App 应先从 list_actions 选择目标 action，再按该 action 的 input_schema 构造 value。

target_action = actions[0]
action_name = target_action["name"]

frame_value = build_value_from_schema(target_action["input_schema"])

response = client.run_action_chunk(
    action_name,
    frames=[frame_value],
    frame_rate=float(target_action.get("frame_rate") or 1),
    timeout_ms=1000,
)

print(response.ok, response.payload, response.message)

run_action_chunk 返回 payload 示例：

{
  "accepted_frames": 1
}

停止当前动作：

client.stop_action(reason="user_requested_stop", timeout_ms=1000)

stop_action 返回 payload 示例：

{
  "stopped": true
}

九、调用 Health 工具

response = client.get_health(timeout_ms=1000)
if response.ok:
    for item in response.payload.get("msg", []):
        print(item)

get_health 返回 payload 示例：

{
  "msg": [
    {
      "level": "warning",
      "component_name": "front",
      "message": "camera frame is stale",
      "timestamp": 1782216088.05
    }
  ]
}

十、Collection 工具

采集在 Server 端进行。App 只传需要采集的协议对象名和 episode 信息。

names = [
    item["name"]
    for item in observations + actions
    if item["type"] in {"joint_state", "image", "joint_position"}
]

client.start_collection(
    names,
    collection_id="demo_collection",
    episode_id="episode_000001",
    task_prompt="demo task",
    task_description="manual data collection",
    frame_rate=30,
    timeout_ms=1000,
)

status = client.get_collection_status(timeout_ms=1000)
print(status.payload)

client.stop_collection(timeout_ms=1000)

start_collection 返回 payload 示例：

{
  "collection_id": "demo_collection",
  "episode_id": "episode_000001",
  "recording": true
}

get_collection_status 返回 payload 示例：

{
  "collection_id": "demo_collection",
  "episode_id": "episode_000001",
  "running": true,
  "duration": 12.5,
  "per_name_counts": {
    "observation.robot.joint_state": 750,
    "observation.front.image": 375,
    "action.robot.joint_position": 750
  }
}

stop_collection 返回 payload 示例：

{
  "collection_id": "demo_collection",
  "episode_id": "episode_000001",
  "recording": false,
  "resource_id": "collections/manual/demo_collection/episode_000001"
}

十一、Resource 数据传输

App 不扫描远端文件系统。日志、采集数据、模型文件、标定文件、导出源数据都通过 Resource 工具传输。只有 Server 的 manifest.capabilities.resources 为 true 时，App 才能读取这些文件类资源。

resources = client.list_resources(limit=100, timeout_ms=1000)
for resource in resources.payload.get("resources", []):
    print(resource["resource_id"], resource.get("metadata", {}))

archive = client.prepare_resource_archive(
    resource_id="some/resource/id",
    format="zip",
    timeout_ms=30000,
)

resource_id = archive.payload["resource"]["resource_id"]
chunk = client.read_resource(resource_id, offset=0, limit=1024 * 1024, timeout_ms=1000)
print(chunk.payload["encoding"], chunk.payload["eof"])

十二、App 开发检查清单

  • 导入 ClientInterface 和 RcpProtocolClient，不要直接依赖 controller。
  • 通过发现或手动地址连接 Server。
  • 用 list_tools 和 Manifest 判断 Server 能力。
  • 用 list_observations/list_actions 构建 UI 和校验输入。
  • 调用工具时只使用协议对象名。
  • 只请求当前页面需要的 observations。
  • 远端数据传输走 Resource 工具。
  • 外部平台格式映射放在 App 边界，App 和 Server 之间保持 RCP 协议格式。
