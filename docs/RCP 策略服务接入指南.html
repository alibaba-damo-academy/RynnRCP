RCP 策略服务接入指南

本文说明 RCP Server 如何发现、加载和运行机器人绑定策略，以及 App 如何通过协议启动策略、更新实时输入和停止策略。

策略服务只负责 obs dict -> action chunk。策略不直接访问 channel、controller、串口或相机。 策略输出统一按 run_action_chunk 入参形状返回，再由 RCP ActionService 下发。 这里的策略指可运行的 RL / VLA / policy 控制策略，不是 Manifest 里的 model_refs（URDF、MJCF、mesh、标定等本体资源）。

一、最小设计

策略接入者只需要做四件事：

  1. 把策略放到一个文件夹。
  2. 写 policy.yaml，声明需要哪些 observation、接收哪些运行时输入、允许输出哪些 action。
  3. 写 policy.py，实现 step(obs)。
  4. 在 Server 配置里加入策略目录。

策略属于机器人构型。每个策略是一个文件夹，文件夹里至少有策略描述文件和推理脚本。

robots/my_robot/policies/
  stand/
    policy.yaml
    policy.py
    weights.onnx
  walk/
    policy.yaml
    policy.py
    weights.onnx
  dance/
    policy.yaml
    policy.py
    weights.onnx
    motion.npz

Server 配置只需要写策略目录：

policies:
  paths:
    - ./policies

PolicyService 启动时扫描 policies.paths 下所有 policy.yaml，并把可用策略暴露给协议层。相对路径以 Server 配置文件所在目录为基准；如果 Server 由内存配置启动，则以机器人本地目录为基准。

二、接入前先确认三件事

策略不是直接读相机、串口或共享内存。策略只消费 RCP 已经暴露出来的 Observation，并输出 RCP 已经暴露出来的 Action。

1. 确认可读取的 Observation

先调用 list_observations，找到策略需要的状态和图像。

{
  "observations": [
    {
      "name": "observation.robot.joint_state",
      "type": "joint_state",
      "value_schema": {
        "type": "object",
        "fields": {
          "joint_positions": {"type": "array", "items": "float", "shape": [6], "unit": "rad"}
        }
      }
    },
    {
      "name": "observation.front_camera.image",
      "type": "image"
    }
  ]
}

然后在 policy.yaml 里按组件和对象名引用它们。用户不需要手写完整 RCP key，PolicyService 会拼成 observation.<component>.<name>：

inputs:
  observations:
    - component: robot
      name: joint_state
    - component: front_camera
      name: image

2. 确认可执行的 Action

再调用 list_actions，找到策略最终要调用的完整 Action 名和单帧 value 结构。

{
  "actions": [
    {
      "name": "action.robot.joint_position",
      "type": "joint_position",
      "input_schema": {
        "type": "object",
        "fields": {
          "joint_positions": {"type": "array", "items": "float", "shape": [6], "unit": "rad"}
        }
      }
    }
  ]
}

策略输出的 name 必须直接写完整 Action 名：

{
  "name": "action.robot.joint_position",
  "frame_rate": 50,
  "frames": [
    {"joint_positions": [0, 0, 0, 0, 0, 0]}
  ]
}

3. 确认 App 运行时要传什么

只有 App 需要动态改变的内容才写到 runtime_inputs，例如速度、方向、prompt、max_steps。固定配置不要塞到协议里，直接写在策略代码或策略目录文件中。

输入建议写法原因
行走速度runtime_inputs.velocity_xyz，配置 stale_after_msApp 会实时更新，断连后应回到默认值。
转向速度runtime_inputs.yaw_rate，配置 stale_after_ms连续控制量，不能永久沿用旧值。
VLA 任务文本runtime_inputs.prompt，不配置 stale_after_ms任务文本通常传一次后持续生效。
策略权重路径放在策略目录里，由 load(policy_dir) 读取不是运行时输入。

三、策略描述文件

policy.yaml 描述策略名称、入口、输入和输出。RL 和 VLA 都返回 run_action_chunk 入参形状，区别只是 frames 数量不同。

RL 单帧策略示例

RL 策略每次推理返回 1 帧 action chunk。PolicyService 按返回值里的 frame_rate 控制下一次推理时间。

policy_id: walk
name: Walk Policy
entrypoint: policy.py:WalkPolicy

inputs:
  observations:
    - component: robot
      name: joint_state
  runtime_inputs:
    velocity_xyz:
      type: array
      items: float
      shape: [3]
      default: [0, 0, 0]
      stale_after_ms: 500
    yaw_rate:
      type: float
      default: 0
      stale_after_ms: 500

outputs:
  actions:
    - component: robot
      name: joint_position

VLA 多帧策略示例

VLA 策略一次推理返回多帧 action chunk。PolicyService 等这段 chunk 的时间窗口结束后，再做下一次推理。

policy_id: pick_place
name: Pick Place VLA
entrypoint: policy.py:PickPlacePolicy

inputs:
  observations:
    - component: robot
      name: joint_state
    - component: front_camera
      name: image
  runtime_inputs:
    prompt:
      type: string
      default: PickPlace

outputs:
  actions:
    - component: robot
      name: joint_position
字段必选说明
policy_id是策略唯一 ID。App 调用 start_policy 时使用。
name是展示名称。
entrypoint是推理类入口，格式为 文件.py:类名。
inputs.observations是Observation 引用列表，每项写 component 和 name。
inputs.runtime_inputs否App 运行时传给策略的输入，例如 prompt、速度向量、yaw rate。这里不用 params，避免和协议请求外层 params 混淆。
stale_after_ms否某个运行时输入多久没更新就回到 default。速度、方向这类连续控制建议配置，prompt 这类任务输入通常不需要。
outputs.actions是Action 引用列表，每项写 component 和 name。

字段怎么写

字段怎么写用户需要注意什么
policy_id短小稳定，例如 walk、pick_placeApp 后续用它启动策略。不要用中文、路径或版本号当 ID。
name人类可读名称，例如 Walk Policy只用于展示，不参与协议匹配。
entrypointpolicy.py:WalkPolicy冒号前是文件名，冒号后是类名。文件路径相对当前策略目录。
inputs.observations- component: robot
name: joint_state		后台解析为 observation.robot.joint_state，并用 list_observations 校验。
inputs.runtime_inputs使用 float/int/bool/string/array/object/bytes类型写法和 RCP value_schema 保持一致。
outputs.actions- component: robot
name: joint_position		后台解析为 action.robot.joint_position，并用 list_actions 校验。

完整 policy.yaml 示例

policy_id: walk
name: Walk Policy
entrypoint: policy.py:WalkPolicy

inputs:
  observations:
    - component: robot
      name: joint_state
  runtime_inputs:
    velocity_xyz:
      type: array
      items: float
      shape: [3]
      default: [0, 0, 0]
      stale_after_ms: 500
    yaw_rate:
      type: float
      default: 0
      stale_after_ms: 500

outputs:
  actions:
    - component: robot
      name: joint_position

四、策略脚本接口

用户实现一个简单类即可。只有 step(obs) 必须实现，load(policy_dir) 和 reset(runtime_inputs) 是可选钩子。

方法必选说明
load(policy_dir)否策略加载时调用一次，可在这里加载权重、ONNX 文件或其它资源。
reset(runtime_inputs)否每次 start_policy 或策略切换前调用，用于清空策略内部状态。
step(obs)是执行一次推理，返回 run_action_chunk 入参形状。

RL 单帧输出

class WalkPolicy:
    def load(self, policy_dir):
        pass

    def reset(self, runtime_inputs):
        pass

    def step(self, obs):
        return {
            "name": "action.robot.joint_position",
            "frame_rate": 50,
            "frames": [
                {"joint_positions": [0, 0, 0, 0, 0, 0]}
            ]
        }

VLA 多帧输出

class PickPlacePolicy:
    def load(self, policy_dir):
        pass

    def reset(self, runtime_inputs):
        pass

    def step(self, obs):
        return {
            "name": "action.robot.joint_position",
            "frame_rate": 50,
            "frames": [
                {"joint_positions": [0, 0, 0, 0, 0, 0]},
                {"joint_positions": [0.1, 0, 0, 0, 0, 0]}
            ]
        }

step(obs) 接收的 obs 包含两类数据：

{
  "observation.robot.joint_state": {
    "joint_positions": [0.1, -1.5, 1.7, 0.7, -0.2, 0.0]
  },
  "velocity_xyz": [0.2, 0.0, 0.0],
  "yaw_rate": 0.1
}

输出里的 name 必须是完整 RCP action name，并且必须出现在 outputs.actions 中。对于 SO101 关节控制，就是 action.robot.joint_position。

完整 policy.py 示例

from pathlib import Path


class WalkPolicy:
    def load(self, policy_dir):
        self.policy_dir = Path(policy_dir)
        self.last_runtime_inputs = {}

    def reset(self, runtime_inputs):
        self.last_runtime_inputs = dict(runtime_inputs or {})

    def step(self, obs):
        state = obs["observation.robot.joint_state"]["joint_positions"]
        velocity = obs.get("velocity_xyz", [0, 0, 0])
        yaw_rate = obs.get("yaw_rate", 0)

        # 示例只返回当前位置。真实策略在这里调用 ONNX / PyTorch / 自定义逻辑。
        joint_positions = list(state)

        return {
            "name": "action.robot.joint_position",
            "frame_rate": 50,
            "frames": [
                {"joint_positions": joint_positions}
            ]
        }

这个类只依赖 Python 入参，不依赖 RCP 内部对象。PolicyService 会负责读取 Observation、合并 runtime_inputs、调用 step(obs)，再把返回结果交给 ActionService。

step 返回值要求

字段要求错误时怎么处理
name必须是完整 RCP Action name，并在 outputs.actions 中拒绝执行本次输出。
frames必须是非空数组，每一项都是目标 Action 的输入对象拒绝执行本次输出。
frame_rate必须大于 0拒绝执行本次输出。

五、协议接口

策略服务只暴露四个协议方法。

方法用途
list_policies列出策略描述和当前状态。
start_policy启动策略。如果已有策略运行，则切换到新策略。
update_policy_inputs更新运行时参数。只保留最新值，不排队。
stop_policy停止当前策略。

list_policies

{
  "method": "list_policies",
  "params": {}
}
{
  "ok": true,
  "payload": {
    "policies": [
      {
        "policy_id": "walk",
        "name": "Walk Policy",
        "inputs": {
          "observations": [
            {"component": "robot", "name": "joint_state", "key": "observation.robot.joint_state"}
          ],
          "runtime_inputs": {
            "velocity_xyz": {
              "type": "array",
              "items": "float",
              "shape": [3],
              "default": [0, 0, 0]
            }
          }
        },
        "outputs": {
          "actions": [
            {"component": "robot", "name": "joint_position", "key": "action.robot.joint_position"}
          ]
        }
      }
    ],
    "active_policy_id": "stand",
    "last_error": ""
  }
}

start_policy

启动策略，或从当前策略切换到另一个策略。启动后默认持续推理，直到调用 stop_policy 或切换到另一个策略。切换时 Server 会先加载并 reset 新策略，成功后再停止旧策略。

{
  "method": "start_policy",
  "params": {
    "policy_id": "walk",
    "runtime_inputs": {
      "velocity_xyz": [0, 0, 0],
      "yaw_rate": 0
    }
  }
}
{
  "ok": true,
  "payload": {
    "active_policy_id": "walk"
  }
}

update_policy_inputs

实时输入更新当前运行策略的最新值，不进入队列。后续推理都会使用这个最新值，直到 App 再次更新、策略停止、策略切换，或该输入按 stale_after_ms 回到默认值。

例如行走 RL 策略收到 velocity_xyz = [0.2, 0, 0] 后，后续每次 step() 都会按这个速度推理；要停下需要更新为 [0, 0, 0]，或等待超时回到默认值。

runtime_inputs 不做“单次生效”语义。需要触发一次性动作时，使用已有 ActionService，例如 action.robot.home、action.robot.move_to 或其他自定义 action。

{
  "method": "update_policy_inputs",
  "params": {
    "runtime_inputs": {
      "velocity_xyz": [0.2, 0, 0],
      "yaw_rate": 0.1
    }
  }
}
{
  "ok": true,
  "payload": {
    "active_policy_id": "walk",
    "runtime_inputs": {
      "velocity_xyz": [0.2, 0, 0],
      "yaw_rate": 0.1
    }
  }
}

stop_policy

{
  "method": "stop_policy",
  "params": {}
}
{
  "ok": true,
  "payload": {
    "stopped_policy_id": "walk"
  }
}

六、切换规则

App 不应该自己执行 stop_policy 再 start_policy。这样会扩大控制空窗。

正确方式是直接调用 start_policy(dance)。Server 内部执行：

stand 正在运行
App 调用 start_policy(dance)
PolicyService 加载 dance
PolicyService reset dance
stand 停止
dance 接管输出

如果新策略加载失败或 reset 失败，旧策略继续运行。

七、运行时行为

PolicyService 运行循环：
  -> 按 policy.yaml 读取最新 observations
  -> 合并最新 runtime_inputs
  -> 调用 active_policy.step(obs)
  -> 得到 run_action_chunk 参数形状
  -> 检查 name 是否在 policy.yaml 的 outputs.actions 解析结果中
  -> 调用 ActionService/run_action_chunk
  -> 按 frames 数量和 frame_rate 控制下一次推理时间

策略输出统一为 run_action_chunk 的入参形状。RL 返回 1 帧，VLA 返回多帧。

节奏也统一由返回值决定：len(frames) / frame_rate 是这次输出覆盖的动作时长。RL 返回 1 帧且 frame_rate=50，下一次推理约在 20ms 后；VLA 返回 20 帧且 frame_rate=50，下一次推理约在 400ms 后。

# RL：1 帧 chunk
{
  "name": "action.robot.joint_position",
  "frame_rate": 50,
  "frames": [
    {"joint_positions": [0, 0, 0, 0, 0, 0]}
  ]
}

# VLA：多帧 chunk
{
  "name": "action.robot.joint_position",
  "frame_rate": 50,
  "frames": [
    {"joint_positions": [0, 0, 0, 0, 0, 0]},
    {"joint_positions": [0.1, 0, 0, 0, 0, 0]}
  ]
}

配置了 stale_after_ms 的输入超时时，使用 policy.yaml 中声明的默认值。例如行走策略没有继续收到速度指令时，velocity_xyz 回到 [0, 0, 0]，策略保持站立。

九、接入检查清单

检查项期望结果
策略目录目录下存在 policy.yaml 和 policy.py。
entrypoint能导入到对应类，例如 policy.py:WalkPolicy。
Observationinputs.observations 每项都有 component 和 name，解析后的 key 能在 list_observations 中找到。
Actionoutputs.actions 每项都有 component 和 name，解析后的 key 能在 list_actions 中找到。
运行时输入类型只使用 float/int/bool/string/array/object/bytes。
连续控制输入速度、方向、力这类输入设置了 stale_after_ms 和安全 default。
step 输出返回 name、非空 frames、合法 frame_rate。

十、边界

  • 协议不暴露 ONNX、TensorRT、PyTorch 等运行时细节。
  • 策略依赖问题先不进入协议，默认本地环境可运行。
  • 策略服务不直接写机器人控制代码，真实执行仍走 ActionService。
  • 实时参数只保留最新值，不保证每次 App 更新都被策略消费。
  • 实时参数只有持续生效一种语义，不增加额外配置。
