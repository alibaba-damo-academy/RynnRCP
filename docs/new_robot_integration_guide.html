RynnRCP 新构型机器人接入指南

本文用 SO101 作为贯穿示例，说明一个新机器人本体如何接入 RynnRCP： 先完成最小平台接入，再进入主臂遥操、ROS2 或 LCM 等进阶操作。

目录

1. 先看全局 2. 需要准备哪些文件 3. 编写控制类 4. 编写 robot_config 5. 接入相机 6. 运行方式 7. 接入后怎么用 8. ROS2 / LCM 接入 9. 验收 Checklist

1. 先看全局

RynnRCP 的作用是把不同机器人本体封装成统一工具。上层平台或应用不需要直接调用机器人 SDK， 只需要通过 RCP Core 调用统一能力，例如获取状态、获取图像、下发动作。

1. 本体 SDK已有串口、CAN、EtherCAT、ROS driver 或厂商 Python SDK。
2. 控制类封装成 start、get_joint_positions、set_joint_positions、stop。
3. RCP Core读取 robot_config.yaml，启动动作、状态、相机、设备服务。
4. RynnBot把 RCP Core 的状态、图像、动作能力暴露给平台。
5. 使用方通过平台获取状态、查看图像并下发动作。
推荐优先采用 module 接入：把机器人 SDK 包一层 Python 控制类，再用 YAML 指向这个类。 这种方式最直接，不要求先搭建 ROS2 或 LCM 系统。

先跑通最小接入

对大多数新机器人，第一步只需要接入一个“执行端”：它能读状态、读相机、执行动作， 并通过 RynnBot 接入平台。SO101 中这个执行端就是从臂。

层次SO101 示例作用
本体控制 SO101Controller 读取关节状态，接收动作并控制机器人。
RCP Core so101_config.yaml 读取从臂状态、执行动作、读取相机、上报设备信息。
平台插件 rynnbot_config.yaml 配置平台连接信息，让平台能够访问端侧工具。
启动入口 run_rcp_so101.py 启动 RCP Core 和 RynnBot 插件。

进阶操作：主臂遥操

主臂遥操不属于最小接入。只有需要主从臂遥操或数据采集时，才额外接入 TeleopPlugin。 SO101 的主臂只负责读取操作者动作，从臂负责执行动作。没有主臂的机器人可以跳过这部分。

进阶能力需要增加的文件什么时候需要
主臂遥操 so101_leader_config.yaml、run_teleop_leader.py 需要用主臂控制从臂时。
从臂遥操执行 teleop_config.yaml、run_teleop_follower.py 需要接收主臂动作并录制遥操数据时。

2. 需要准备哪些文件

文件分为“必须准备”和“按场景准备”。最小接入只需要执行端控制类、从臂 robot_config、RynnBot 配置和启动脚本。 

robots/so101/
├── config/
│   ├── so101_config.yaml          # 必须：执行端 RCP Core 配置
│   ├── rynnbot_config.yaml        # 必须：RynnBot 平台连接配置
│   ├── so101_leader_config.yaml   # 进阶：主臂 RCP Core 配置，仅遥操需要
│   └── teleop_config.yaml         # 进阶：主从臂遥操网络配置
├── run_rcp_so101.py               # 必须：启动执行端 RCP Core + RynnBot
├── run_teleop_leader.py           # 进阶：启动主臂 + 遥操 Web UI
├── run_teleop_follower.py         # 进阶：启动执行端遥操接收
├── controller.py                  # 必须：执行端控制类
└── leader_reader.py               # 进阶：主臂读取类，仅遥操需要

文件责任表

文件是否需要编写说明
controller.py 必须 把机器人 SDK 封装成控制类；新构型需要改成自己的执行端控制类。
so101_config.yaml 必须 告诉 RCP Core 如何读取状态、接入相机、下发动作。
rynnbot_config.yaml 必须 填写平台连接信息。字段值由平台分配。
run_rcp_so101.py 必须 启动执行端 RCP Core 和 RynnBot 插件。通常复制 SO101 示例后替换配置路径即可。
so101_leader_config.yaml 进阶 只有需要主臂遥操时才写；普通平台接入不需要。
teleop_config.yaml 进阶 只有需要主从臂遥操或遥操数据采集时才写。
run_teleop_leader.py / run_teleop_follower.py 进阶 遥操启动脚本；没有主臂或不做遥操时可忽略。

相机 USBCamera front / wrist USB 相机直接配置；厂商相机用 module 封装。
配置文件 so101_config.yaml 替换 robot_type、module_name、init_args、相机设备号。

3. 编写控制类

控制类是接入的核心。RynnRCP 不关心底层是串口、CAN、SDK 还是 ROS driver； 只要求 YAML 中配置的方法能够被调用。

从臂控制类需要做什么

方法作用RynnRCP 什么时候调用
start() 连接硬件、初始化 SDK、启动后台控制循环。 RCP Core 启动 input/output adapter 后调用。
get_joint_positions() 返回一维状态数组，例如 6 个关节 + 夹爪。 按 interval 周期读取，写入 observation.state。
set_joint_positions(positions) 接收一帧动作并发送给机器人。 收到 run_action_chunk 或遥操动作时逐帧调用。
stop() 停止运动、释放资源、断开连接。 RCP Core 退出时调用。

SO101 从臂控制类示例

控制类可以直接放在 robots/so101/controller.py。 RynnRCP 不要求控制类必须放在 rcp_motion 下，只要 sys_path 和 module_name 能 import 到这个类即可。 下面是它对 RynnRCP 暴露的关键接口形态： 

# robots/so101/controller.py
class SO101Controller:
    def __init__(self, mode: str = "real", frequency: int = 100, robot_name: str = "so101"):
        self.mode = mode
        self.frequency = frequency
        self.robot_name = robot_name
        self.qPos_feedback = None
        self.qPos_command = None

    def start(self) -> None:
        # 连接机器人，启动后台循环，持续读取反馈并发送命令。
        pass

    def get_joint_positions(self) -> list[float]:
        # 返回当前关节状态，写入 observation.state。
        return self.qPos_feedback.astype(float).tolist()

    def set_joint_positions(self, positions) -> None:
        # 接收 action 中的一帧动作，保存为待执行目标。
        self.qPos_command = positions

    def stop(self) -> None:
        # 停止后台循环，释放硬件资源。
        pass
状态维度和动作维度必须固定。例如 SO101 如果约定为 6 个关节 + 夹爪， 那么 observation.state 和 action 都应按同一顺序解释。

进阶：主臂读取类

遥操主臂通常不执行平台动作，只负责读取状态。主臂读取类也可以直接放在 robots/so101/leader_reader.py，YAML 中只配置输入，不配置输出。 

module_name: leader_reader.SO101LeaderReader
init_args:
  robot_name: so101
method_name: get_joint_positions
out_key: observation.state

4. 编写 robot_config

robot_config.yaml 告诉 RCP Core：从哪里读状态、从哪里读相机、动作要发给哪个方法。 对 module 接入来说，最重要的是 module_name、init_args、 method_name 和 out_key。 示例配置文件位于 robots/so101/config/，因此 sys_path: .. 表示把 robots/so101/ 加入 Python import path。

SO101 从臂配置

config_type: robot_config
robot_type: so101

servers:
- name: action_server
  inputs:
  - protocol: module
    adapter: ModuleGenericInputAdapter
    params:
      sys_path:
      - ..
      module_name: controller.SO101Controller
      init_args:
        mode: real
        frequency: 100
        robot_name: so101
      start_call:
      - method_name: start
        method_kwargs: {}
      destroy_call:
      - method_name: stop
        method_kwargs: {}
      method_name: get_joint_positions
      method_kwargs: {}
      interval: 0.01
      out_key: observation.state
  outputs:
  - protocol: module
    adapter: ModuleStepOutputAdapter
    params:
      sys_path:
      - ..
      module_name: controller.SO101Controller
      init_args:
        mode: real
        frequency: 100
        robot_name: so101
      instance_lock: true
      start_call:
      - method_name: start
        method_kwargs: {}
      destroy_call:
      - method_name: stop
        method_kwargs: {}
      method_name: set_joint_positions
      dynamic_arg:
      - from_key: action
        arg: positions
      static_args: []
      post_chunk_delay_s: 0.1
字段怎么理解
inputs 把机器人状态读进 RCP buffer。SO101 写入 observation.state。
outputs 把 RCP 收到的动作发给机器人。SO101 调用 set_joint_positions。
dynamic_arg 把 action 映射为方法参数。这里会调用 set_joint_positions(positions=...)。
instance_lock 控制类不是线程安全时建议开启，避免同时读写 SDK。

5. 接入相机

相机也是写在 robot_config.yaml 里。SO101 默认使用两路 USB 相机： front 和 wrist。 

- name: sensor_server
  inputs:
  - protocol: port
    adapter: PortImageInputAdapter
    params:
      port_type: USBCamera
      init_args:

        encoding: bgr8
        fps: 30
        brand: usb_camera
        rotate: 0
      out_key: observation.images.front
  - protocol: port
    adapter: PortImageInputAdapter
    params:
      port_type: USBCamera
      init_args:
        device_id: '1'
        width: 640
        height: 360
        encoding: bgr8
        fps: 30

      out_key: observation.images.wrist

class SO101DepthCamera:
    def start(self):
        pass

        # 返回 ok, width, height, encoding, frame
        return True, 640, 480, "bgr8", frame

    def stop(self):
        pass

6. 运行方式

运行时先启动最小平台接入。确认平台能获取状态、图像并下发动作后， 再进入主从臂遥操等进阶操作。

最小运行：启动执行端 RCP Core + RynnBot 插件

# robots/so101/run_rcp_so101.py
from rynnrcp import RynnRCP, RcpCore, RynnBot

app = RynnRCP(
    rcp_core=RcpCore(config_file="./config/so101_config.yaml"),
    plugins=[
        RynnBot(config_file="./config/rynnbot_config.yaml"),
    ],
)

app.start()
cd RynnRCP/robots/so101
python run_rcp_so101.py
对没有主臂、暂时不做遥操的机器人，到这里就已经完成运行闭环： RCP Core 负责本体能力，RynnBot 负责平台接入。

进阶运行：启动主臂遥操

只有需要“用主臂控制从臂”或“录制遥操数据”时，才需要启动下面两个进程。 主臂进程读取操作者动作，从臂进程接收动作并执行。 

# robots/so101/run_teleop_leader.py
from rynnrcp import RynnRCP, RcpCore
from comm_plugin.teleop_plugin import TeleopPlugin

teleop = TeleopPlugin(
    config_file="./config/teleop_config.yaml",
    role="leader",
    enable_web_ui=True,
    web_port=5001,
    open_browser=True,
)

app = RynnRCP(
    rcp_core=RcpCore(config_file="./config/so101_leader_config.yaml"),
    plugins=[teleop],
)

app.start()
cd RynnRCP/robots/so101
python run_teleop_leader.py

进阶运行：启动执行端遥操接收

# robots/so101/run_teleop_follower.py
from rynnrcp import RynnRCP, RcpCore, TeleopPlugin

app = RynnRCP(
    rcp_core=RcpCore(config_file="./config/so101_config.yaml"),
    plugins=[
        TeleopPlugin(config_file="./config/teleop_config.yaml", role="follower"),
    ],
)

app.start()
cd RynnRCP/robots/so101
python run_teleop_follower.py

遥操网络配置

teleop:
  leader_host: 127.0.0.1
  follower_host: 127.0.0.1
  leader_port: 9101
  follower_port: 9102
  control_hz: 30
  image_hz: 10
主臂和从臂在不同机器上时，把 leader_host 和 follower_host 改成对应机器的局域网 IP。主从双方都启动后，遥操数据才会开始交换。

7. 接入后怎么用

机器人接入 RynnRCP 后，默认通过 RynnBot 平台使用；如果启用了 TeleopPlugin， 还可以通过遥操界面使用。

平台能调用什么

能力数据来源作用
get_state observation.state 读取机器人当前状态，例如关节角和夹爪状态。
get_image observation.images.front / wrist 读取相机图像，用于遥控、观察或模型输入。
run_action_chunk action 下发一段动作序列，RCP Core 会逐帧调用控制类的执行方法。
get_device_info device_monitor_server 读取设备信息和机器人类型。

平台接入怎么用

启动 run_rcp_so101.py 后，执行端会加载 RynnBot 插件。 平台侧可通过设备配置访问端侧工具，执行取状态、取图和下发动作。 平台接入参数来自 rynnbot_config.yaml，包括产品、设备和密钥信息。

进阶操作：遥操怎么用

  1. 启动从臂遥操执行端：python run_teleop_follower.py。
  2. 启动主臂遥操端：python run_teleop_leader.py。
  3. 打开 Web UI：http://127.0.0.1:5001。
  4. 点击开始后，主臂状态会通过 TeleopPlugin 发送给从臂执行。
  5. 需要采集数据时，在 Web UI 中开始录制，结束后导出 episode。

8. ROS2 / LCM 接入

module 是推荐首选。如果已有成熟 ROS2 或 LCM 系统，可以把状态和动作改成 topic/channel 接入。 这时 RCP Core 不直接调用机器人 SDK，而是订阅已有中间件中的状态消息，并把动作发布回中间件。

方式适合场景RynnRCP 负责什么
ROS2 已有 ROS2 driver，状态通过 topic 发布，动作通过 topic 接收。 订阅 JointState 等消息，把字段写入 observation.state；把 action 发布成 JointTrajectory。
LCM 已有 LCM channel，或机器人系统内部已经使用 LCM 做低延迟通信。 订阅 channel 并 decode 消息；把动作 chunk encode 成 LCM 消息发布。

ROS2：让 RynnRCP 识别自定义消息

YAML 里的 msg_type 必须是当前 Python 环境可以 import 的类路径。 如果使用自定义 ROS2 消息，例如 custom_robot_msgs/msg/MyJointState.msg， 需要先编译并 source 对应 workspace，再启动 RynnRCP。 

# 1. 编译包含自定义 msg 的 ROS2 workspace
cd ~/custom_robot_ros2_ws
colcon build --symlink-install

# 2. 在同一个终端 source ROS2 和自定义 workspace
source /opt/ros/humble/setup.bash
source ~/custom_robot_ros2_ws/install/setup.bash

# zsh 用户也可以使用 setup.zsh
# source /opt/ros/humble/setup.zsh
# source ~/custom_robot_ros2_ws/install/setup.zsh

# 3. 验证 Python 能 import 自定义消息
python - <<'PY'
from custom_robot_msgs.msg import MyJointState
print(MyJointState)
PY

# 4. 再启动 RynnRCP
cd /path/to/RynnRCP/robots/so101
python run_rcp_so101.py

验证通过后，robot_config.yaml 里就可以把 msg_type 写成自定义消息类路径。 

msg_type: custom_robot_msgs.msg.MyJointState
mappings:
- field: joint_position
  out_key: observation.state
关键点是“source 后再启动 RynnRCP”，并且 source 要发生在同一个终端或同一个启动脚本里。 source 会设置 AMENT_PREFIX_PATH、PYTHONPATH 等环境变量， RynnRCP 才能通过 Python import 找到自定义消息。

ROS2：订阅状态

下面配置表示：RCP Core 订阅 /so101/joint_states， 从 sensor_msgs.msg.JointState.position 取关节数组， 写入统一状态键 observation.state。 

- name: action_server
  inputs:
  - protocol: ros2
    adapter: Ros2GenericInputAdapter
    params:
      topic: /so101/joint_states
      msg_type: sensor_msgs.msg.JointState
      mappings:
      - field: position
        out_key: observation.state
  outputs: []

field 支持普通字段、嵌套字段和切片： 

mappings:
- field: position
  out_key: observation.state
- field: position[0:6]
  out_key: observation.arm
- field: position[6]
  out_key: observation.gripper
ROS2 输入消息需要有 header.stamp.sec 和 header.stamp.nanosec，RynnRCP 会用它们作为这条状态数据的时间戳。

ROS2：发布动作

输出侧把 run_action_chunk 里的 action 解释为多帧关节目标。 Ros2JointTrajectoryOutputAdapter 会生成一个 trajectory_msgs.msg.JointTrajectory，并把每一帧写到 JointTrajectoryPoint.positions。 

outputs:
- protocol: ros2
  adapter: Ros2JointTrajectoryOutputAdapter
  topic: /so101/joint_trajectory
  type: trajectory_msgs.msg.JointTrajectory
  mappings:
  - key: action
    out_field: positions

如果 action chunk 是三帧，例如 [[...], [...], [...]]， 发布出去的 JointTrajectory.points 也会有三帧。 每一帧的 time_from_start 会根据动作频率自动设置。

LCM：订阅状态

LCM 接入方式和 ROS2 类似，只是把 topic 换成 channel，把 ROS2 消息类型换成可 import 的 LCM Python 类型。下面配置表示订阅 SO101_JOINT_STATE，从 position 字段提取状态。 

- name: action_server
  inputs:
  - protocol: lcm
    adapter: LcmGenericInputAdapter
    params:
      topic: SO101_JOINT_STATE
      msg_type: lcm_msgs.msg.JointState
      mappings:
      - field: position
        out_key: observation.state
  outputs: []
LCM 输入消息需要有 header.stamp_sec 和 header.stamp_nanosec。如果你的 LCM 类型字段名不同，需要先适配消息类型， 或改用 module 封装转换逻辑。

LCM：发布动作

输出侧把 action 转成一个 LCM JointTrajectory 消息。 每一帧动作会被写入 trajectory 的一个 joint point，out_field 一般写 position。 

outputs:
- protocol: lcm
  adapter: LcmJointTrajectoryOutputAdapter
  topic: SO101_JOINT_TRAJECTORY
  type: lcm_msgs.msg.JointTrajectory
  mappings:
  - key: action
    out_field: position

LCM：项目内已有消息

RynnRCP 已带一组通用 LCM 消息，位于 common/lcm/lcm_types。 推荐优先使用这些消息配合 LCM adapter，因为字段结构和 adapter 期望一致。

消息类路径主要字段适用场景
lcm_msgs.msg.Header stamp_sec、stamp_nanosec、frame_id 状态、图像和轨迹消息的统一时间戳。
lcm_msgs.msg.JointState name、position、velocity、effort 发布或订阅机器人关节状态。
lcm_msgs.msg.JointTrajectory joints，每个元素是 JointState 发布多帧动作 chunk。
lcm_msgs.msg.Image height、width、encoding、data 传输未压缩图像。
lcm_msgs.msg.CompressedImage format、data 传输 JPEG/PNG 等压缩图像。

使用这些通用消息前，需要保证 Python 能 import lcm_msgs。 可以安装为 editable 包，也可以临时加入 PYTHONPATH。 

# 推荐：安装通用 LCM 消息包
cd /path/to/RynnRCP
python -m pip install -e common/lcm/lcm_types

# 或临时加入 PYTHONPATH
export PYTHONPATH=/path/to/RynnRCP/common/lcm/lcm_types:$PYTHONPATH

# 验证
python - <<'PY'
from lcm_msgs.msg import JointState, JointTrajectory, Image, CompressedImage
print(JointState, JointTrajectory, Image, CompressedImage)
PY

项目里还包含运动链路相关的 LCM 消息，位于 common/lcm/lcmMotion， 包括 act_command、act_request、 robot_feedback、state_feedback。 SO101 目录下也有一份生成消息：rcp_motion/robots/so101/lcm_msgs， 包括 act_command、act_request、 robot_feedback、robot_observation、state_feedback。

LcmGenericInputAdapter 默认要求消息里有 header.stamp_sec 和 header.stamp_nanosec。 通用 lcm_msgs.msg.JointState 满足这个结构；部分运动链路消息使用 sec、nanosec 顶层字段，不能直接套用 generic adapter 的默认时间戳逻辑。 这种情况建议用 module 做一层转换，或新增专用 adapter。

接入前检查

  1. 先确认状态 topic/channel 已经在发布，且频率稳定。
  2. 确认消息类型能被当前 Python 环境 import，例如 sensor_msgs.msg.JointState、custom_robot_msgs.msg.MyJointState 或 lcm_msgs.msg.JointState。
  3. 确认状态字段维度和动作字段维度一致，例如都是 6 个关节 + 夹爪。
  4. 先只配置 input，验证 observation.state 能更新；再配置 output，验证动作能被机器人 driver 收到。
  5. 如果 ROS2/LCM 消息结构复杂，先用切片或中间转换节点整理成简单的一维关节数组。
如果没有现成 ROS2 / LCM 系统，不建议为了接入 RynnRCP 额外搭一套中间件。 直接使用 module 接入会更简单，也更容易定位问题。

9. 验收 Checklist

  • 控制类可以单独启动、读取状态、执行一帧动作、停止。
  • robot_config.yaml 中的 module_name、init_args、method_name 都能正确 import 和调用。
  • observation.state 维度固定，并已说明每一维含义和单位。
  • 相机可以稳定输出 observation.images.front、observation.images.wrist 或自定义图像键。
  • 执行端 run_rcp_so101.py 可以启动，平台可以获取状态和图像。
  • run_action_chunk 下发动作后，控制类会按帧收到 positions。
  • 进阶遥操：如果启用主臂遥操，主臂和执行端 TeleopPlugin 可以建立连接，主臂动作能驱动执行端。
  • 退出进程时，控制类和相机资源可以正常释放。
完成必选检查后，新构型就具备平台调用能力；完成进阶遥操检查后，再具备主从臂遥操能力。 后续新增传感器或更换通信协议时，只需要扩展对应的 input/output 配置。
